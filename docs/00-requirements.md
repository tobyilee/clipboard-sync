# Clipboard Sync — 요구사항 정의서

> 상태: 요구사항 확정 (구현 미착수)
> 작성일: 2026-09-29 / 개정: 2026-09-29 (파일·이미지 20MB, 수신 후 서버 삭제, 타입별 on/off), 2026-09-29 (advisor 리뷰 반영: 로컬 우선 규칙, 서명, 소스 포맷 변환)

## 1. 목적

Mac과 Windows를 동시에 사용하는 개인 사용자가, 한쪽 OS에서 복사(copy)한 내용을 다른 OS에서 바로 붙여넣기(paste) 할 수 있도록 **양방향 원격 클립보드 동기화** 서비스를 제공한다.

## 2. 범위

### 2.1 In scope (v1)
- macOS 네이티브 앱 (메뉴바 상주)
- Windows 네이티브 앱 (시스템 트레이 상주)
- Cloudflare 기반 서버 (동기화 및 임시 저장)
- 양방향 자동 동기화, 최근 항목 조회, on/off 제어, 종단간 암호화(E2EE)
- 타입별(텍스트 / 이미지 / 파일) 동기화 on/off 및 미디어 최대 크기 설정 (Mac 메뉴바에서 편집)

### 2.2 Out of scope (v1)
- 다중 사용자 / 회원가입 / 계정 시스템
- 폴더 복사, 미디어 최대 크기(기본 20MB, 최대 50MB)를 넘는 파일/이미지
- 모바일(iOS/Android), Linux, 웹 클라이언트
- 앱스토어 배포, Apple 공증(notarization) (개인 설치용; 서명은 NFR-4 참조)
- 비밀번호 관리자 항목 자동 제외 (v1 제외, 추후 검토)
- 검색 가능한 대용량 히스토리

## 3. 사용자 및 사용 환경
- 사용자: 본인 1명 (single user), 기기는 Mac 1대 + Windows 1대 이상을 가정 (v1 검증 대상은 2대)
- 기기 식별/인증: 사용자 계정 없이 **공유 passphrase**로 페어링

## 4. 기능 요구사항

### FR-1. 자동 동기화
- 한 기기에서 복사가 발생하면 자동으로 서버에 업로드되고, 상대 기기의 클립보드에 자동 반영된다. 사용자는 상대 기기에서 일반 Cmd/Ctrl+V 만으로 붙여넣는다.
- 양방향(Mac→Windows, Windows→Mac) 모두 지원한다.
- 동기화로 반영된 항목이 다시 업로드되는 **에코/무한 루프를 방지**해야 한다.

### FR-2. 지원 콘텐츠 타입과 기본값
| 타입 | 비고 | 기본값 |
|---|---|---|
| 텍스트 (일반 텍스트 + 리치 텍스트/HTML) | 서식·링크 유지 | **ON (끌 수 없음)** |
| 이미지 | 스크린샷 등 클립보드 이미지 | **OFF** |
| 파일 | Finder/Explorer에서 복사한 파일 | **OFF** |

- 이미지/파일 동기화 on/off는 **vault 전체 설정**이다 (양쪽 기기에 동일하게 적용). 편집은 **Mac 메뉴바 앱에서만** 가능하고, Windows 앱은 현재 값을 읽기 전용으로 표시한다.
- 설정 값을 아직 받지 못한 상태(최초 실행 직후, 서버 조회 실패)에서는 **텍스트만** 동기화한다.
- 타입 판별 규칙
  - 파일이 복사된 경우(Finder/Explorer): 파일 항목으로 취급한다. 파일이 꺼져 있으면 **항목 전체를 무시**한다 (파일명 텍스트로 대체 전송하지 않는다).
  - 이미지 표현이 텍스트/HTML과 함께 있는 경우: 이미지가 꺼져 있으면 이미지 표현만 제외하고 텍스트 표현을 보낸다. 텍스트 표현이 없으면 무시한다.
  - 소스 앱이 HTML 없이 RTF만 제공하는 경우(TextEdit, Notes, Pages, Word 등)에는 RTF를 HTML로 변환해 서식을 유지한다. 이미지가 TIFF(Mac) 또는 DIB(Windows)로만 제공되면 PNG로 변환한다.
  - 파일 이름은 NFC로 정규화해 전송한다 (Finder의 자모 분리 한글 파일명이 Windows에서 깨져 보이는 것을 방지).

### FR-3. 크기 제한
- **텍스트(일반/HTML)만 있는 항목: 1 MiB 이하.**
- **이미지/파일이 포함된 항목: 기본 20 MB (합계)**. Mac 메뉴바에서 5 / 10 / 20 / 50 MB 중 선택한다. 서버의 절대 상한은 50 MB이다.
- 여러 파일은 합계 기준이며 폴더는 지원하지 않는다.
- 제한 초과 시 업로드하지 않고 **알림으로 사유를 표시**한다. (타입이 꺼져 있어서 무시된 경우는 알림 없이 조용히 무시한다.)

### FR-4. 메뉴바/트레이 UI
Mac(메뉴바)과 Windows(시스템 트레이)는 아래 항목을 **동일하게** 제공한다.
- 동기화 전체 on/off 토글
- **일시정지 (N분)**: 지정한 시간 동안 동기화 중지 후 자동 재개
- **방향별 토글**: 보내기(send) / 받기(receive)를 각각 활성/비활성 (기기별 로컬 설정)
- **최근 항목 목록**: 최근 20개 (양쪽 기기에서 발생한 항목 포함), 항목 종류/미리보기/출처 기기/시각 표시
- 목록의 항목을 선택하면 해당 항목을 **로컬 클립보드에 복원** (단, FR-5의 서버 삭제된 항목은 이 기기에 로컬 캐시가 남아 있을 때만 가능하며, 없으면 "서버에서 삭제됨"으로 비활성 표시)
- 로그인 시 자동 시작 (끄는 옵션 제공), 종료 메뉴
- 상태 표시(연결됨/오프라인/일시정지/오류/업로드·다운로드 진행 중)

**Mac 메뉴바 전용 (vault 전체 설정 편집)**
- "동기화 대상": 텍스트(항상 켜짐, 비활성 체크), 이미지·스크린샷, 파일
- "미디어 최대 크기": 5 / 10 / 20(기본) / 50 MB
- Windows 트레이는 위 값을 읽기 전용으로 보여주고 "Mac에서 변경"이라고 안내한다.

### FR-5. 히스토리, 보관, 수신 후 삭제
- 서버는 최근 **20개 항목, 24시간** 보관 후 자동 삭제한다 (둘 중 먼저 도달하는 조건 기준). 보관 항목은 암호문 상태로만 저장된다.
- **이미지/파일이 포함된 항목의 본문(body)은 수신 기기가 클립보드 적용을 마치는 즉시 서버에서 삭제**한다 (용량 확보). 항목 목록용 header(종류·미리보기)는 만료 시까지 남는다.
  - "paste 완료"는 실제 Cmd/Ctrl+V 시점을 서버가 알 수 없으므로 **"수신 기기의 클립보드에 적용 완료"** 로 정의한다.
  - 수신 기기는 복원을 위해 복호화한 내용을 로컬 캐시(24시간)에 보관한다. 서버 본문이 삭제되면 다른 기기는 그 항목을 다시 받을 수 없다.
  - 아직 적용되지 않은 항목(받기 off, 일시정지, 기기 오프라인, 더 최신 항목에 밀린 경우)의 본문은 24시간 만료 또는 20개 초과 시 삭제된다.
- 텍스트 항목의 본문은 히스토리 복원을 위해 24시간 유지한다.

### FR-6. 오프라인 처리
- 상대 기기가 오프라인이거나 앱이 꺼져 있어도 서버가 항목을 보관(보관 기간 내)한다.
- 재접속 시 놓친 항목을 가져와 히스토리에 반영하되, **클립보드에는 가장 최신 항목만** 적용한다.
- **로컬 우선 규칙 (2026-09-29 사용자 승인)**: 오프라인·일시정지·앱 종료 중에 이 기기에서 사용자가 새로 복사한 내용이 있으면, 재접속 시 **원격 항목으로 그 내용을 덮어쓰지 않는다** (원격 항목은 히스토리 목록에만 반영). 네트워크 오류로 업로드하지 못한 가장 최근 복사 1개는 보관했다가 재접속 시 먼저 업로드한다. 일시정지·보내기 off·타입 off 때문에 보내지 않은 복사는 나중에 업로드하지 않는다.

### FR-7. 페어링
- 첫 기기의 앱이 고엔트로피 **passphrase를 생성**(diceware 7단어)해 보여주고, 각 기기에서 **동일한 passphrase**를 입력한다. 직접 정하는 경우 24자 이상만 허용한다 (근거: [01-tech-spec.md](./01-tech-spec.md) D-3/D-4). 이 passphrase로부터 암호화 키와 서버 인증 토큰을 파생(KDF)한다.
- 파생 키/토큰은 macOS Keychain, Windows Credential Manager에 저장한다.
- passphrase 자체는 서버로 전송하지 않는다.

## 5. 비기능 요구사항

### NFR-1. 보안
- **종단간 암호화(E2EE)**: 클립보드 내용(텍스트, 파일명, 파일 내용, 이미지 등)과 vault 설정은 기기에서 암호화하여 전송한다. 서버는 암호문과 최소한의 메타데이터(크기, 시각, 항목 ID, 출처 기기 ID)만 다룬다.
- 전송 구간은 TLS.
- 서버 API는 passphrase 파생 토큰으로 인증한다.

### NFR-2. 성능
- 정상 네트워크에서 복사 후 상대 기기 클립보드 반영까지 체감상 수 초 이내 (목표: 2초 이내, **1 MiB 이하 항목 기준**). 대용량 항목은 네트워크 속도에 비례하며 진행 상태를 표시한다.
- 실시간 전달을 위해 WebSocket 등 push 방식을 사용한다 (Cloudflare Durable Objects 사용을 전제로 설계).

### NFR-3. 안정성
- 네트워크 단절 시 자동 재연결.
- 클립보드 감시로 인한 과도한 CPU/배터리 사용을 피한다.

### NFR-4. 배포
- 개인 설치용. 앱스토어 배포와 Apple 공증(notarization)은 v1 범위 밖 (수동 설치, 로그인 시 자동 시작). 단 macOS 앱은 **안정적인 서명 ID**(무료 Apple Development 인증서 또는 자체 서명 인증서)로 서명해, 재빌드 후에도 pasteboard 허용·파일 접근·Keychain 권한이 유지되게 한다.

## 6. 기술 스택 (권장안 — 확정)
| 영역 | 선택 |
|---|---|
| macOS 앱 | Swift (SwiftUI/AppKit, NSStatusItem, NSPasteboard) |
| Windows 앱 | C# / .NET 10 LTS (시스템 트레이, Clipboard API) |
| 서버 | Cloudflare Workers + Durable Objects (TypeScript) + **R2 (대용량 본문)** |
| 암호화 | 클라이언트 측 KDF + AEAD (PBKDF2 + AES-256-GCM, 상세는 01-tech-spec) |

## 7. 미결/추후 검토 사항
- 비밀번호 관리자(concealed/transient) 클립보드 항목의 자동 제외
- passphrase 분실/변경 시 절차 (키 교체 시 기존 서버 데이터 폐기)
- 기기 3대 이상: 수신 후 삭제 정책상 **먼저 적용한 기기가 서버 본문을 삭제**하므로 나머지 기기는 받지 못한다 (v1 한계)
- 알림 방식(macOS Notification Center / Windows toast) 세부 사양
- Cloudflare R2 사용을 위해 계정에서 R2를 활성화해야 하며 결제 수단 등록이 필요할 수 있음 (무료 한도 내 사용 예상, 배포 시 확인)
