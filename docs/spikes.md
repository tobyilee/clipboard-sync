# M0 스파이크 결과

> 형식: 가정 / 결과 / 설계 변경 여부. 설계 변경이 필요하면 spec을 먼저 수정하고 결정 로그에 D-번호를 추가한다.
> 계획: [02-implementation-plan.md](./02-implementation-plan.md) §2.2

| # | 가정 | 상태 | 결과 | 설계 변경 |
|---|---|---|---|---|
| S-1 | Workers Free에서 R2 binding + 20/50MB 스트리밍 업/다운로드 (DO 메모리 미사용) | ✅ 통과 | Free 플랜에서 R2 binding 동작. `R2.put(key, request.body)` 스트리밍으로 20 MiB(PUT 4.3s/GET 1.7s), 50 MiB(10.3s/1.6s), 51 MiB(9.9s/1.6s) 모두 성공, 다운로드 바이트 일치, DELETE 후 404. 이 스파이크는 Worker→R2만 검증(DO 미경유). 실제 설계도 Worker가 스트리밍하고 DO는 메타만 다루므로 DO 메모리와 무관. 51 MiB 하드 캡 초과 거부(413)와 Free 일일 한도는 M2에서 확인 | 없음 (D-15 유지) |
| S-2 | macOS pasteboard 권한 동작, 안정 서명 ID로 재빌드 시 권한 유지 | ✅ 통과 (경고 재현은 미확인) | **API:** `accessBehavior`/`detect*`는 SDK 헤더상 macOS 15.4+ (문서의 "26"은 오류). `detect*`는 패턴 감지용이라 종류 판별은 `types`로 가능(텍스트/파일 URL/PNG+TIFF 확인, 내용 읽기 없이). **서명:** Apple Development ID의 지정 요구사항이 인증서 기반(cdhash 아님)이며, 코드가 다른 4개 빌드(A~D) 사이에서 Keychain 읽기와 Desktop/Downloads TCC 허용이 유지됨(재빌드 후 3개 폴더 35ms, 프롬프트 없음. 최초 Desktop·Downloads 접근 때만 프롬프트). **경고:** macOS 26.6.2에서 새 앱이 첫 실행부터 `accessBehavior == .alwaysAllow`(서명/ad-hoc/Finder 직접 실행 모두), 읽기 경고 없음, "다른 앱에서 붙여넣기" 설정 화면 없음, MDM 없음. `.ask` 경고는 재현하지 못함. 15.4~15.x 동작 미검증 | spec 7장 수정, D-29 추가 |
| S-3 | Windows CF_HTML/PNG/CF_DIBV5/CF_HDROP 읽기·쓰기 | ✅ 통과 (합성 데이터 기준, 실제 소스 덤프는 미수집) | **자가 테스트 전 항목 PASS**(raw Win32, Cloud PC): CF_HTML(UTF-8 바이트 오프셋 유효, 한글·이모지 fragment 왕복), `PNG`(등록 id 49406)+`CF_DIBV5`(17) 동시 기록 후 PNG·DIBV5 모두 알파 포함 픽셀 일치, HDROP(wide) 한글·이모지 파일명·폴더 유지 + `Preferred DropEffect` 읽기, 마커 왕복, `CanUploadToCloudClipboard=0` 읽기. **관찰:** ① DIBV5만 쓰면 Windows가 `CF_DIB`/`CF_BITMAP`을 합성하는데 합성 `CF_DIB`는 **알파가 전부 255**(원본과 픽셀 6080개 불일치) → PNG가 없으면 `CF_DIB`보다 `CF_DIBV5`를 우선 읽어야 함. ② straight(비-premultiplied) 알파 판별: 부분 투명 픽셀 중 색>알파 픽셀 존재 여부. ③ 쓰기 1회 = `WM_CLIPBOARDUPDATE` 1회, 15ms 내 연속 쓰기 3회 = 3회(0/7/5ms) → 100ms 디바운스로 합쳐짐. **미수행:** Edge/Explorer/Snipping Tool 등 실제 소스 덤프(`out/`에는 메모장 텍스트 1건뿐), Office(Cloud PC에 미설치). 교차 붙여넣기(WordPad/Edge/그림판/Explorer)는 사용자가 "문제 없음"으로 판단했으나 항목별 결과는 기록되지 않음. 코드는 `spike/s3` 브랜치, 결과는 그 브랜치 `windows/spikes/s3/out/` | 없음. M3/M4에서 Edge·Explorer·Office 실소스 fixture로 CF_HTML 파서, DIB→PNG, HDROP(폴더·잘라내기) 처리를 재검증 (spec 4.5는 폴더/잘라내기 규칙이 없음 — 그때 결정) |
| S-4 | Swift↔C# PBKDF2/HKDF/AES-GCM 상호운용 | ✅ 통과 | **Swift:** CommonCrypto `CCKeyDerivationPBKDF`(600k) + CryptoKit `HKDF<SHA256>`(빈 salt) + `AES.GCM`이 Node(`crypto`) 독립 참조 구현과 35개 항목 전부 일치. **C#(.NET 10.0.401, Cloud PC):** `Rfc2898DeriveBytes.Pbkdf2`(바이트 오버로드) + `HKDF.DeriveKey`(빈 salt) + `AesGcm`이 같은 벡터 35개 항목 전부 통과. passphrase 2종(ASCII / NFKD가 바이트를 바꾸는 `Café 한글 ＡＢＣ①`)에 대해 master·enc_key·auth_token·vault_id, header/body/config 3파트의 AAD 바이트(필드에서 재구성)·seal 결과 바이트 일치·상대 암호문 open·AAD 1바이트 변조 거부. PBKDF2 600k: Mac 약 0.2초, Cloud PC 약 0.14초. 벡터는 `protocol/test-vectors.seed.json`(정식 `test-vectors.json`의 씨앗). 스파이크 코드는 `spike/s4` 브랜치(`windows/spikes/s4`)에 있으며 `main`에는 넣지 않음 | spec §3.2 명확화, D-30 추가 (HKDF 빈 salt, NFKD→바이트, 소문자 hex) |
| S-5 | 클라우드 Windows RDP 클립보드 리디렉션 off 동작 | 🔶 부분 (off 확인) | **off:** Windows App의 Cloud PC 설정에서 Clipboard를 해제하면 Mac↔Cloud PC 텍스트 복사가 전달되지 않음을 사용자가 확인(2026-09-29). **미확인:** 리디렉션 on 상태의 에코 루프 동작, CF_HTML/이미지/파일 등 텍스트 외 형식, 방향별 확인 | 없음 (지금까지) |
